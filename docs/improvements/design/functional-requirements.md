# Hayer functional and Material 3 Expressive implementation backlog

This ledger preserves every item from the 3 September 2026 request. Duplicate user numbering has been normalized into twenty independently verifiable requirements. Implement these alongside the 24 catalog design plans; do not treat the catalog plans as replacing this list.

## 1. Public session links must open the join flow

Current evidence: `https://hayer.almou.sa/join/ZQB` returns HTTP 200 without an HTTP redirect, but its document declares `<base href="/app/">`. The reported change to `/app/join/ZQB` is therefore happening in the Flutter bootstrap/router layer. The app has only `/join/:code`; it has no normalization for an incoming `/app/join/:code` location.

Implementation:

- Introduce one `normalizeInitialLocation(Uri)` function accepting `/join/{code}`, `/app/join/{code}`, and Android/iOS universal-link forms, returning `/join/{CODE}`.
- Feed the platform default route through this function before `GoRouter` handles it. Add a redirect fallback for `/app/join/:code` to the canonical route.
- Keep the public shared/QR URL as `https://hayer.almou.sa/join/{CODE}`. Do not generate `/app/join` links.
- Adjust the web gateway/app shell so booting under `/join/{code}` does not rewrite browser history to the mount path. Preserve `/app/` only for asset resolution.

Acceptance:

- A clean browser opened directly at `/join/Q3W` stays on the public URL and renders a join form with `Q3W` filled.
- `/app/join/Q3W` recovers to the same form rather than home or a blank page.
- A verified Android App Link opens the installed app at the same form.
- Tests exercise production base href, refresh, cold start, and warm-app links.

## 3. Make all maps genuinely interactive with MapLibre 0.27.0

Current evidence: `maplibre_gl: ^0.27.0` is already declared and used. The widget redraws annotations and animates the camera whenever its center/radius props change, which can fight gestures; it only commits marker drag at the end and has no camera-idle center interaction.

Implementation:

- Retain MapLibre 0.27.0, which is the current published release as of this audit.
- Enable pan and pinch zoom; keep rotate/tilt disabled unless a screen explicitly needs them.
- Never auto-recenter from annotation-only updates after the initial camera fit.
- Track gesture start/end and camera idle. When editable, allow panning the map to move the search center and update the parent only when the gesture settles.
- Preserve map state across parent rebuilds and avoid clearing/re-adding every annotation on each drag frame; update existing annotations instead.

Acceptance:

- One-finger pan and pinch zoom remain smooth on Android, iOS, and web.
- The camera does not snap back after the user pans.
- Repeated center/radius edits do not leak annotations or controllers.

## 4. Scanning a Hayer QR must navigate to join

Current evidence: scanner detection has no integration test. It stops the camera and calls `go('/join/$code')`; code parsing is tested only for `/join/...`, while the deployed web path can become `/app/join/...`. The stylized QR may also reduce scan reliability.

Implementation:

- Route every scanned payload through the shared normalizer from requirement 1.
- Accept canonical public URLs, `/app/join` recovery URLs, bare three/six-character codes, whitespace, and lowercase.
- On the first valid scan, provide success haptic, stop scanning, and navigate exactly once. If navigation fails, reset `_handled`, restart the camera, and show a localized error.
- Add a visible fallback action for manual code entry.

Acceptance:

- An actual QR generated by the lobby opens the prefilled join form on a physical Android device.
- Duplicate frames cause one navigation only.
- Invalid QR content keeps scanning without freezing.

## 5. Resize and move the search circle directly on the map

Current evidence: radius is selected by five choice chips. The map renders a draggable center dot, but not a resizable circle.

Implementation:

- Remove radius chips.
- Represent the radius as a continuously editable integer clamped to 500–10,000 metres and rounded to a sensible step (100 m below 2 km, 500 m above it).
- Render a center handle and an edge handle. Dragging the center/map changes the center; dragging the edge handle computes geodesic distance from center and updates radius.
- Add `onRadiusChanged(int)` to `SearchAreaMap`, update the polygon live at a throttled frame rate, and show the localized radius in the map overlay.
- Provide keyboard/semantics increase/decrease actions as an accessible fallback.

Acceptance:

- Dragging the edge changes the server request radius and visual circle together.
- Dragging the center preserves radius.
- The handle stays usable in LTR/RTL and at minimum/maximum radius.
- Pure geometry tests cover distance, clamp, rounding, and radius polygon.

## 9. Majority sessions must remain joinable after current participants finish

Current evidence: for multiplayer `afterDeck`, the server sets the entire session to `completed` whenever every participant currently present has completed. `join()` calls `_ensureActive`, so the next guest is rejected as “already complete.”

Implementation:

- Separate a participant finishing their deck from closing the session's join window.
- Do not auto-complete a multiplayer `afterDeck` session merely because all currently joined participants finished. Keep it active/joinable until host closure or expiry; results are valid and live while active.
- Introduce an explicit host close/finalize action if final completion is required for persistence/UI. Solo completion stays automatic. Instant-match completion behavior remains separate and should be product-tested.
- Recompute majority against actual voters and continue sending result/participant events when later guests join or vote.

Acceptance:

- Host and guest can finish, a third guest can then join and swipe.
- Existing participants see the third guest and updated tallies in real time.
- Solo, unanimous instant match, expiry, capacity, and duplicate-name rules still pass.
- Add a server integration regression test for this exact sequence.

## 17. Follow Serverpod streaming best practices

Current evidence: the server `watch()` yields only future Message Central events. Lobby/results call `listen()` once and permanently switch to polling after an error; they never rebuild the stream connection. Serverpod's current real-time tutorial recommends creating the message stream before yielding the initial full snapshot (avoids a snapshot/update gap) and an indefinite client reconnect loop that catches `MethodStreamException` and retries after a delay.

Reference: https://docs.serverpod.dev/tutorials/tutorials/real-time-communication

Implementation:

- Change the stream model so a subscriber receives an initial session snapshot/revision and then ordered incremental events. Create the Message Central stream before loading/yielding the snapshot.
- Centralize client subscription in a repository/controller using `await for`, catch `MethodStreamException`, back off with cancellation-aware delay, and reconnect while the owning screen is alive.
- Use polling only as a bounded degraded fallback, cancel it immediately after stream recovery, and prevent overlapping loads.
- Compare revisions, ignore stale/duplicate events, and force a snapshot reload on gaps.

Acceptance:

- A subscriber never misses an update between initial load and stream attachment.
- Killing/restarting the server reconnects both lobby and results without reopening the screen.
- Widget disposal cancels retry/poll timers and stream work.
- Server integration tests cover initial snapshot, event order, reconnect, duplicates, and revision gaps.

- Migrate buttons, icon buttons, app bars, cards/lists, chips, text fields, switches, progress/loading, dialogs/sheets, and snackbar feedback to their `M3E*` counterparts where the package has a stable component.
- Use Expressive shapes, spring motion, state layers, minimum target sizes, and reduced-motion behavior consistently. Preserve iOS-native date/time presentation where intentionally adaptive.
- Add screen-level goldens for English/Arabic and light/dark on Android dimensions.

Acceptance:

- No consumer-app file accidentally mixes incompatible Flutter/material and material_ui types.
- Every interactive Android screen uses the Expressive theme and appropriate M3E components, not merely `useMaterial3: true`.
- Visual, widget, semantics, and reduced-motion tests pass across all screens.
